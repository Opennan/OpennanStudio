# @opennan/provider-opennan

The OpenNan provider of OpenNan Studio (spec §5.5): **Sign in with OpenNan**, the account and its credits, and AI jobs on the opennan.com public API. OpenNan Community License (spec §3). Browser-safe: the main entry uses `fetch` only; `@opennan/provider-opennan/testing` (Node) is a fake OpenNan server for tests.

- **API client** `createOpenNanApi({ baseUrl })`: JSON in and out, the key as a bearer token to the API's own origin only, the error envelope `{"error":{"type","message","code"}}` as `OpenNanApiError` (402 `insufficient_balance` → `InsufficientCreditsError`, `Retry-After` → `retryAfterSeconds`). Bases must be `https:` (plain `http:` only on loopback, for tests). Messages never carry a key (`redactKeys`).
- **Device flow** `startDeviceSignIn(api, { deviceName, client: "desktop" | "web" | "cli", signup })` and `createDevicePoller(api, start)`: polls `POST /v1/auth/device/token` every `interval` s, adds 5 s on `slow_down`, ends on `expired_token`/`invalid_grant` (expired) or `access_denied` (denied), waits out a 429, retries network failures three times, and `pollNow()` (window focus, tab visible) polls as soon as the interval (and any Retry-After) has passed, for background tabs whose timers run late; it never polls early.
- **Account** `getAccount(api, key)` (`GET /v1/account`: email, name, photo, balance, key) and `revokeKey(api, key)` (`DELETE /v1/auth/key`, best effort).
- **`OpenNanSession`**: the state machine every host shares: `restoring → signed-out | signed-in`, `start() → starting → waiting → signed-in | error` (`expired`, `denied`, `network`, `rate-limited`, `origin`, `unknown`). The host supplies a `CredentialStore` (desktop: an internal safeStorage slot in main; web: IndexedDB or sessionStorage; CLI: a 0600 file). Sign-out and switch account revoke the key, then clear it. Notices (`insufficient-credits`, `sign-in-needed`) let hosts show toasts. No status, notice, or error contains the key.
- **`createOpenNanProvider(session, { prepareMedia })`**: provider id `opennan`, every open capability except `render.export` (local) and the local-only ones (`media.stabilize`), plus every `opennan.*` capability. `audio.transcribe` is cloud captions (an on-device provider still wins its default route). `run()` jobs: images, video, and music are tasks (`POST /v1/{images,videos,music}/generations`, then `GET /v1/tasks/{id}?wait=50`, cancel through `POST /v1/tasks/{id}/cancel`); speech and sound effects answer with the audio. Signed out → `OpenNanSignInRequiredError` (a `CapabilityUnavailableError`: "Connect OpenNan: run `opennan-studio login` or sign in from Studio's account chip."); 402 → "Not enough credits…" and an `insufficient-credits` notice; 401 → signed out. Output links are kept only when `https:`. `models(capability)` lists `GET /v1/models?category=…`. The `opennan.*` project pipeline capabilities (story plan, storyboard, copy-video, smart scene video) run only on projects stored on OpenNan, so they answer `OpenNanProjectPipelineError` (unavailable): Studio projects stay on the device.

- **Media tools (0.2.0)**: `captions.translate`, `audio.isolate-voice`, `video.upscale` (1080p / 2k / 4k), `video.remove-background`, `video.lipsync`, `audio.separate` (vocals / all, results with `role`), and `audio.transcribe` (`provider.audio.transcribe`, words grouped into segments). A media input is a `MediaSourceRef` (`source`, or `videoSource` + `audioSource` for lip sync; `image` / `endImage` for image-to-video and image edit) that the host's `prepareMedia` turns into a file, or an https link (`audioUrl`, `videoUrl`) passed straight through. Stages read "Preparing", "Uploading", then the tool's own ("Reading", "Transcribing", "Isolating", …). Before a task is created, the price is checked again against the prepared file: above `input.expectedMaxUsd` the job fails with `price_changed` ("The price changed: ≈ $x. Run again to accept.") and nothing is sent. Every task POST carries a fresh `Idempotency-Key` and is never retried. Cancel asks the server once the task exists: 200 cancels (refunded), 409 keeps the job running (`cancellable: false`); a failed task rejects with `JobFailedError(message, { refunded })`.
- **Uploads** `uploadMedia(api, key, prepared, { signal, cache })`: `POST /v1/uploads` → `PUT upload_url` with exactly the given Content-Type, no Authorization, no credentials, no redirects, no referrer, https only (loopback only for a loopback API) → `POST /v1/uploads/{id}/complete` (a 409 sends the file once more). Tool inputs send no `project_id` and no `scope`: the server keeps them as temporary uploads. The PUT may go to the single-use upload gateway (`https://upload.opennan.com/u/<token>`, phase 9a): a 410 `upload_url_used` (or a second PUT of a used URL) starts one new upload. The provider caches uploads by SHA-256 of the bytes and the type for one task only, so the next task uploads again. A key without `api:project` gets "This key cannot upload media (it needs the api:project scope): sign in with OpenNan."
- **Prices** `provider.price(request)`: tools from `GET /v1/tools`, models from `GET /v1/models` (price blocks), through the provider-sdk estimate rule; lists cached ten minutes, no key needed; a tool that is not live answers `unavailable`, a list that cannot be read `unknown`. `provider.voices()` reads `GET /v1/audio/voices`.
- **Quotes (0.3.0)**: the amount is the server's own `POST /v1/quotes` answer for the body the run would send (`price_usd`, the settle; `hold_usd` rides along as `estimate.holdUsd` for a balance check; `estimate.source: "quote"`). The prompt is left out (a typed prompt reuses the quote), image inputs are a placeholder link, per-unit tools are quoted with the decode margin (`paddedSeconds`, capped at the longest input) both for the label and for the pre-upload re-check. Quotes are cached per canonical body for a minute; an older server (404) is not asked again for ten minutes, a 429 waits `Retry-After`; on 404 / 429 / 503 the never-under estimate answers (`source: "estimate"`). `createQuoteClient`, `quoteBody` are exported.
- **Error codes (0.3.0)**: Studio reads the server's `code` (never null on `/v1`) and shows its own words (`OPENNAN_ERROR_COPY`, `openNanErrorMessage`): `tier_not_offered` → "This quality isn't available, pick another.", `permission_denied` on an upload → "Sign in again to allow uploads.", `rate_limit_exceeded` → "Try again in N s", upload codes → "Run it again", and (9a) the storage codes (`storage_quota_exceeded`, `upload_daily_limit`, `temp_storage_exceeded`, `free_storage_pool_full`, `upload_gateway_unavailable`, `multipart_required`, `upload_parts_invalid`, `upload_url_used`, `project_data_quota_exceeded`, `project_too_large`). `OpenNanApiError.details` carries the envelope's `error.details` (`{kind, ids}`, `{path}`, `{revision}`). Server text is shown only when it is customer text without internals (`safeServerText`). Cancel: `task_busy_retry` is asked again after `Retry-After` (0.25–5 s, three times at most), `task_not_cancellable` keeps the job running ("it will finish and be charged"), `task_already_finished` GETs the task and ends the job in its final state; message matching remains for an older server only.
- **Fake server** (`@opennan/provider-opennan/testing`): uploads, the seven tool tasks with strict bodies and stages, `GET /v1/tools`, model price blocks, voices, and knobs: `/__test/fail-next?tool=&kind=`, `/__test/paid-started?tool=`, `/__test/tool-status?id=&status=`, `/__test/drop-translated-line`, `/__test/task-steps?n=`, `/__test/key-scopes?scopes=`, and (0.3.0) `/__test/quotes?status=404|429|503|live`, `/__test/cancel-busy?n=`. `FAKE_TOOL_PRICES` holds its prices; `fakeQuote` / `fakeToolSettle` mirror the server's pricing functions (every error carries a code; cancel refusals carry the cancel codes). Uploads v2 (sha256 dedup, scopes, quotas) through the single-use gateway `/u/<token>` with multipart and `/files/<key>` with ranges live in `testing-cloud.ts`, with knobs under `/__test/cloud/*` (also `handle.cloud`). That module, `testing-shares.ts` and `testing-director.ts` still mirror the server's project, storage, share and director routes; Studio no longer calls them (cloud projects were removed), and they are test-only.

```ts
import { OpenNanSession, createOpenNanApi, createOpenNanProvider } from "@opennan/provider-opennan";

const session = new OpenNanSession({ api: createOpenNanApi(), store, client: "web", deviceName: "Web · Chrome on macOS" });
await session.restore();
registry.register(createOpenNanProvider(session));
await session.start({});          // status → waiting { userCode, verificationUriComplete }
```

Thin client only: inputs go to opennan.com and results come back; no pipeline logic or prompt text lives here (spec §2.1).
